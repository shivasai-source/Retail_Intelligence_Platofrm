The six warnings are all `react(only-export-components)` — files exporting a
component plus a constant or hook: `Sparkline.tsx`, `LiveStatus.tsx`,
`Confirm.tsx`, `Toast.tsx`, `PromotionMatrix.tsx`, `simulation/panels.tsx`.
They affect Vite fast refresh only.

Vite emits one build warning: the single JS chunk exceeds 500 kB. **No code
splitting is configured.**

### ⚠ There is no frontend test suite

No Vitest, Jest, Testing Library or Playwright configuration exists, and no
test file exists anywhere under `frontend/`. This is stated openly inside the
backend suite — `tests/test_filter_reconciliation.py` notes that the
reconciliation logic lives in `frontend/src/store/commandFilters.ts` and that
"this project has no frontend test [suite]", which is why the tests cover the
server-side half.

**Untested by any automated test, in consequence:**
filter reconciliation and recency tie-breaking, the two-scope Command Center
query split, chart rendering, the Simulation Studio mode switch and store
isolation, the report download path, the Calendar's panel layout, and every
component's empty/error state.

## 4. Load-time data validation (runtime, not a test)

`app/tpo/loader.py` validates as it loads:

| Condition | Behaviour |
|---|---|
| A `(Year, Week)` in the fact table with no dim_date match | **Raises** — the analytical month cannot be derived, and a silent fallback would misfile the row |
| A fact row referencing an absent product / store / promotion id | **Warns to stdout**, keeps the row under a blank label — it still carries real money and must not vanish from Trade Spend |
| Missing dataset file | `FileNotFoundError` naming the path and `TPO_DATA_DIR` |

## 6. Reproducing these results

```bash
# Backend — ~11 minutes (the CSV load dominates)
cd backend
../venv/Scripts/python.exe -m pytest tests/ -q

# One module
../venv/Scripts/python.exe -m pytest tests/test_command_center.py -q

# Frontend
cd frontend
npx tsc -b
npm run lint
npm run build
```

The suite is slow because several modules build the full 205,920-row store.
There is no fixture-scoped shared store across modules.
